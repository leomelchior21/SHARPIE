# Final project

Open **Final project** on the module screen, or `/final-project` after signing in. This is a separate module from Final Bosses. Existing modules retain their routes and content.

## Classroom sequence

Each stage is designed for one 45-minute class. All content is in English.


1. **BACKROOMS RUN**: a found-footage runner through a real-time 3D Backrooms (WebGL via three.js, loaded only when the game opens; devices without WebGL fall back to the original 2D renderer). Every gate shows real C# in a code panel. While the student walks the corridor, the next gate's values and condition stay masked (`int energy = ▒▒;`, `if (▒▒▒▒)`); they load with a flash only when the gate approach begins, so each gate is read and solved on the spot. The game opens on a tape library: four short tapes, then **The Deep** (Endless), which unlocks once all four are cleared. The library shows each tape as a labelled Hi8 cassette. Tapes open one at a time: after a clear, BACK TO THE SHELF returns to the library, where the newly opened tape waits with a NEW sticker; the teacher preview (eye button) opens every tape. Choosing a tape plays a 3D tape change rendered with three.js in its own lazily loaded chunk: the chosen cassette slides out of a wooden tape rack and arcs across the table into a brushed-silver Hi8 camcorder, which opens its door; the cassette with its handwritten label and spinning reels slides in, the door latches, the LED turns green and the camera dives into the lens onto a VHS-blue PLAY screen and static, then the tape loads: spinning reels, a block progress bar with a percentage, the level being built step by step (reading the tape, building the corridor, charging the batteries, opening Level 0) and one example to remember from that tape (about 7.5 seconds in all, with synthesized mechanism sounds when sound is on). SKIP, Enter, Space or Escape skip it; reduced motion shows only PLAY; without WebGL a flat cassette plays the same timeline. RETRY TAPE rewinds instead (◀◀ REW, about 1.3 seconds). During a run the screen reads as the camcorder's flip-out LCD: rounded bezel, RGB pixel grid and glare, ▶ PLAY then REC, an SP badge, a W–T zoom bar that follows the pace and a date stamp.

   Each tape adds one idea. Every set gate after the very first starts one step from the edge, so the operator decides the last press (`> 40` starts at 40, `>= 40` at 39). The live TRUE/FALSE light fades out: all of tape 01, only the first gate of tapes 03 and 04, then never.

   | Tape | Focus | Gates | New hazard |
   | --- | --- | --- | --- |
   | 01 Lights On | `>` `<` | Set energy (live light); tutorial | none |
   | 02 Two Doors | `>` `<` | Door pairs: values given, steer into TRUE or FALSE | barriers (jump) |
   | 03 The Edge | `>=` `<=` | Set gates and doors, on the edge | saws |
   | 04 Exactly | `==` `!=` | Set gates and doors | holes |
   | 05 No Light | all | Set gates and doors, no light | drills |
   | 06 Final Cut | all, faster | Set gates and doors, no light | all of them |

   Each hazard has a one-time guide the first time it appears. Opening a set gate with the value right on the edge (40 for `>= 40`, 41 for `> 40`) adds an EDGE BONUS of +5 XP.

   Level 0 is dark: most fluorescents are dead and the camcorder's video light does the lighting. Its three batteries set the beam: full charge throws a long bright beam, two a dimmer one. On the last battery the camera saves power: a weak beam and NIGHTSHOT (the green infrared view) take over, and something sometimes stands far down the corridor. The fluorescents no longer flicker or black out. Only a logic mistake costs a battery: a closed gate, the wrong door, or stopping on the centre pillar. The run freezes on the mistake and shows the substituted evaluation (`40 > 40 → false`, `true && false → false`) with a one-line rule. At zero batteries the camera switches off: no LCD and no OSD, only a narrow patch of near-dark vision, with the gate lights, the hazard lamps and spare batteries still glowing. A spare battery (a white pack with green LEDs on the carpet) waits in the corridor whenever the camera is missing charge, and always when it is dead; walking over it adds a battery and turns the camera back on. A gate missed with the camera already off ends the run. Touching a wall, a chair, a bin or a barrier, or falling into a hole, ends the run on the spot (SIGNAL LOST, saying what was hit); a fall drops the camera down the shaft first. From tape 02 on, jumps fill up to two straights per corridor: caution barriers (jump), giant saws that slide out of one wall with a whine and cover that half of the corridor past the middle (dodge to the other side), holes that go down forever (stay in the air all the way across), and giant electric drills. A drill strikes one lane: a ceiling drill first paints a pulsing red target on the floor, a floor drill shows glowing orange cracks and a rumble, then the gold twist bit plunges or bursts through with a roar, an impact flash, sparks, falling ceiling tiles or flying carpet, and blue electric arcs around its motor. Saws and drills cannot be jumped. Tapes cycle through every hazard they allow; The Deep opens barriers, saws, holes and drills at gates 3, 5, 7 and 9 and mixes them at random. Space or the JUMP button clears them; over a hole the runner must stay in the air the whole way. A lost tape offers CONTINUE FROM GATE n: it rewinds and restarts just before the gate the runner was heading for, keeping XP, gates read and mistakes; a crash counts against the stars like a mistake. RETRY TAPE starts over. Every run, and every retry, starts behind the door into Level 0, which swings open before the run begins. Every gate raises the pace, inside tapes as well as in The Deep; the camera displays the pace relative to the run's opening speed. Stars: three for no mistakes, two for one, one for two. The Backrooms teach comparisons only: energy gates to set and door pairs to choose (the engine still understands `bool` and `&&`, but no tape or Deep gate uses them, and Field Notes list the six operators). The Deep mixes set gates and door pairs, hides every live result, speeds up each gate and brings back the operators the student misses most (up to four times as often, from the Field Notes); spare batteries appear on the floor like in the tapes; the 670-gate champion title is kept.

   Guided pauses (make it TRUE, steer, two doors, jump, saw, hole, drill) appear once per student: each is saved as soon as it has been shown, so losing a tape and pressing RETRY TAPE restarts that tape immediately, without the briefing or the guides already seen. Saves from the original game with 5+ gates also skip the first tutorial. The menu's Field Notes tab shows right/wrong counts per operator, `bool` and `&&`. Controls: ↑/↓ or W/S energy, ←/→ or A/D steer, Space jumps, T toggles the bool, Escape or P pauses, Enter continues. On iPad the left thumb edits values and the right thumb steers. Switching tabs, losing focus or Pause pauses the game. Look and feel: procedurally textured wallpaper, damp carpet and drop ceilings with normal maps; fluorescent troffers that cast real light and flicker from tape 03; steel gates with LED strips, LED signs, sliding doors and roll-up shutters that colour the corridor TRUE green or FALSE red; hanging turn signs, office chairs, bins, barriers and drifting dust. Post-processing adds bloom and a camcorder pass (grading, chromatic aberration, grain, VHS tracking glitches). Blackouts switch to NIGHTSHOT with an infrared lamp, and a figure appears at the end of the corridor only in failing light. Resolution adapts to hold the frame rate on tablets. Optional synthesized hum, footsteps, doors, jumps and stingers are off by default and remembered per device. Reduced motion disables flicker, glitches, head bob, grain and shake.
2. **SWITCHYARD** (it replaced the IF / ELSE Lab; Live Flow and the Code Builder were retired): a hub with two stations in order.
   - **Quiz** (twenty questions, same answer key) in four rounds of five: Warm-up (comparisons), True or false (`bool` and `if`), Two paths (`if` / `else`), On the edge (boundaries and the feed). After each answer the code traces the lines that ran and skipped, with the condition rewritten for its value. Answering all twenty, right or wrong, earns the yard license and opens the game; the review screen lets a student practise the ones they missed.
   - **The Switchyard** (`src/views/finalproject/switchyard/`): drawn in the style of the if / else explainer video: a cream dotted page, outlined cards with hard shadows, yellow label tags, green IF and orange ELSE. An `if` is a track switch: a small train carries the value along the track, the condition box on its post tests it and turns green (true) or orange (false), and the train rolls to the IF card or the ELSE card, whose text is the message that branch prints. The code editor follows the run like the video: the value lands on line 1, the test is marked true or false, the block that runs is boxed and the other one is marked SKIPPED, and the Output line prints the result. Each level also has its client drawn as a flat cartoon (ticket booth, delivery truck, fan, phone battery, vault, game screen, weather, ride, library book, pool) that reacts to what the program printed, so a wrong rule shows the wrong thing happening. The program builds the track: the `if` line lays the switch, the prints fill the cards and `else` lays the lower branch. A missing `else` leaves a dead end where nothing happens; a misplaced line leaves a gap, and `=` instead of `==` jams the switch. Every run sends a timetable of three trains (just below, at and just above the edge; true, false, true on the bool level) through the real C# engine, one at a time, while a readout shows the test, the test with the value in it, and the result. A number line paints which values take which track.

     | Level | Skill | Tool |
     | --- | --- | --- |
     | 01 First Switch | The five parts of an if / else | Labelled code blocks in order |
     | 02 No Labels | Order matters | Shuffled blocks |
     | 03 Dead End | What else is for | Runs first without else, then lay it |
     | 04 Calibrate | `<` and the edge | Sensor dial: operator and number |
     | 05 Exact Match | `==` versus `=` | Dial with a jamming `=` |
     | 06 Two Ways Round | `!=`, and flipping a test | Dial plus SWAP STATIONS |
     | 07 Yes / No Cargo | A bool is a condition | Pick the if line, swap stations |
     | 08 Wrong Platform | Debug the edge | Watch the incident, then fix the dial |
     | 09 Swapped Signs | One fix reveals the next bug | Watch, swap stations, fix the edge |
     | 10 Write It Yourself | Write it from scratch | Type the if / else, then choose the three trains that prove the edge |

     Before the first run of a level the student predicts which track the spotlight train takes. A level ships when every train reaches the right card and the rule holds for every value in its range; stars count the runs it took (three on the first). A one-question "why?" check follows before the next level opens; its right answer changes position from level to level. Levels open in order; each shipped level adds scenery to the yard.
   Every Switchyard screen fits the viewport on tablets and laptops without scrolling; phones scroll. C# operators always render as typed (`>=`, `!=`), never as ligatures.
3. **SHADOW FEED / OPERATION WHITE HAT** is hidden for now (`SHADOW_FEED_OPEN` in `progress.ts`); its code, saves and audit report stay in place.

Backrooms and the Switchyard hub are available immediately; the Switchyard game opens once the quiz is answered. The Backrooms stage card shows a frame rendered by the 3D game. The shared header is 44 pixels tall.

## Saves and preview

Follows Sharpie's Basic Operations pattern: versioned, profile-scoped localStorage. Key: `sharpie:final-project:v1:<encoded student login>`. The full save stays in the browser. A compact summary (quiz answered/right and missed question numbers, Switchyard levels shipped and stars, Shadow Feed policies, report status, reflection and XP) is mirrored to `sharpie_progress.codes.finalProject` about a second after each change and once when the module opens, the same way Mathler mirrors its steps, so no new table or SQL is needed. The teacher dashboard shows it as a FINAL column with two stages (Quiz, Switchyard), a Module 08 detail panel and extra CSV columns. Summaries saved before the Switchyard carry no levels until the student opens the module again. Backrooms Run is not part of it (see below). Teacher accounts and previews never sync. No new authentication is introduced. XP milestones, selected activity, flow paths/values, builder drafts, quiz answers/attempt counts, audit patches and reflection are persisted. Interrupted runs restart safely while best runs remain saved. Storage errors show an in-app notice.

Backrooms scores 10 XP per gate read right, 15 from a three-gate combo and 20 from six, plus 10 XP per star when a tape is cleared; the best single-run XP is saved. Module XP counts 10 per quiz question, 30 per shipped Switchyard level, and 50 per audit policy. Live Flow and Code Builder XP from older saves is not carried over. Replays do not duplicate module XP. Existing saves retain the XP earned from the retired Boolean Check; resuming that retired activity now opens the C# connection. Backrooms Run is a plain web game inside Sharpie: it sends nothing to Supabase and does not appear on the teacher dashboard, the CSV or the PDF report. Its own save (`src/views/finalproject/backroomStore.ts`, key `sharpie.backroom.v1.<encoded student login>`) keeps tape stars, Field Notes counts, best Endless gate count, total gates, best run XP, operators and coach tips on the device, and its XP is not added to the module XP. Saves from before this split carried Backrooms inside the Final Project save; it moves to the game's save once when the module opens. Stage 1 shows COMPLETE after all four tapes (or three gates in an older save). The Deep's leaderboard lists the top runs played on this device (`sharpie.backroom-scores.v1`). Guests type their name on the menu before any tape plays and each of their Deep runs is recorded under it; teacher previews do not write scores, and teachers can open every tape.

**Teacher preview** is available to the authenticated teacher through the eye button. It opens all three stages in separate in-memory progress; exiting restores the saved student state. Students see only Back in the shared header and cannot enable preview through a URL parameter.

The White Hat Audit Report includes the existing profile name, rules, results, completion and a short saved reflection. **Export image** downloads a standalone SVG. **Print / Save as PDF** uses the browser print dialog. Print styles omit navigation and include the reflection.

## Implementation and validation

Scenario content, behavior, persistence, UI, and canvas rendering are separated under `src/views/finalproject/`. Existing `SyntaxLine` and `executeCSharp` are reused. `public/sharpie-runner.worker.js` adds a bounded block parser and typed IF/ELSE evaluation, including bool/int comparisons, string output and branch scope. It remains a classroom C# subset, not a complete C# compiler. No JavaScript `eval` is used.

Commands:

```text
npm run build
npm test -- --maxWorkers=2
npm run dev -- --host 127.0.0.1 --port 5186 --strictPort
node scripts/final-project-smoke.mjs
```

The browser check uses installed Edge/Chrome and Node's built-in CDP connection. Its dedicated profile and all artifacts stay inside Sharpie (`node_modules/.cache/final-project-browser`, `TestResults/final-project`). The dev-only fixture `scripts/final-project-preview.html` mounts the real module with a synthetic profile, never signs in or touches classroom accounts, and is not included in the Vite production build. Set `SHARPIE_QA_URL` to use another local development server.

Unit/integration checks cover the answer key against the actual worker, all scenario branches, equivalent programs, boundary mistakes, gate generation and speed, storage isolation/recovery, unlocks and duplicate XP. The browser check walks the Switchyard hub and its lock, all twenty questions, level 1 from blocks and level 10 typed through the real C# engine, reloads saves, exercises true/false gates and retry/pause, and captures desktop, iPad, shorter iPad and phone layouts. Device emulation does not replace a physical iPad/Safari check.
